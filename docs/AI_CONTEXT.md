## 2. Проект

**«Нитэн: Путь Двух Душ»** — 3D action-игра на Three.js (браузер, WebGL2), по собственному GDD.
Вдохновение: **Onimusha: Way of the Sword**.

### Мир и персонажи
- **Акира** — герой. Образ Миямото Мусаси: сине-серое кимоно, широкое серое оби, тёмная хакама, дикие волосы, щетина, шрам. Две катаны:
  - **Акацуки** — правая, ЛКМ;
  - **Ёи** — левая, ПКМ (в v0.9 ломается в доме, см. ниже).
- **Перчатка Они** — на левой руке, светящиеся жилы; поглощает души, взаимодействует с порталами, добивает.
- **Юки** — спутница, голос-гид (все подсказки в `say`).
- **Сота** — брат-антагонист, босс главы 4 (двор с колоколом), длинные волосы, рога 2-й фазы, красные глаза.
- **Враги:** Гэнма-копейщик, Хитоцумэ Гаса, Кама-итати, Лучница-рокурокуби (+ враги дома, см. раздел 8).
- **Механики:** удар креста (ЛКМ+ПКМ), Иссэн (Q в момент красного блеска), Мусо Нитэн (R при полной шкале Они), огненный серп (F), лунные цепи (G), стойки (1/2/3), захват цели (Tab), блок (Q), поглощение душ (зажать E).

### GDD
`docs/NITEN_PUT_DVUH_DUSH_GDD_v1.2.md` (~58.8 КБ) — исходный дизайн-документ. Читать перед крупными фичами.

## 4. Сборка

### Полная сборка
```bash
pip install bpy==5.2.2 numpy pillow   # Blender как Python-модуль (Python 3.13)
npm install
cd /data/repo && bash game/build.sh
```
### Только код (используется в 95% случаев)
```bash
cd /data/repo && SKIP_MODELS=1 bash game/build.sh
```
Печатает `dist ok, parts: 8`.

### Что делает build.sh
1. (без `SKIP_MODELS=1`) `blender/build.py` → `niten_assets.glb` → `tools/optimize.mjs` → `.opt.glb`;
   то же для `loot.py` и `house.py`; `fetch_tex.py` — CC0-текстуры.
2. Склеивает модули в один файл:
   ```bash
   cat game/src/gA.js gB.js gC.js gD.js gE.js gS.js gI.js gH.js gF.js > game/src/game.js
   ```
   (порядок критичен: `gF.js` — последний, это главный цикл).
3. `npx esbuild game/src/game.js --bundle --minify --format=esm --target=es2022 --outfile=dist/niten.js`
4. Python-скрипт режет base64 GLB и JS на части:
   - `dist/assets/part00..07.js` — основные модели (niten_assets.opt.glb, ~5.5 МБ);
   - `dist/assets/loot00..01.js` — лут;
   - `dist/assets/house00..05.js` — дом (niten_house.opt.glb, 3.9 МБ);
   - `dist/assets/game00..02.js` — код игры;
   - `dist/index.html` (~1.5 КБ) — загрузчик частей + boot-скрипт через Blob URL.
   - Каждая часть ≤ 990 000 символов base64 / 600 000 символов JS.
5. Пишет единый `NITEN_3D_single.html` (все ассеты инлайном, ~15.8 МБ) — **не коммитится**, используется только для headless-тестов.
6. `rm -f dist/niten.js`.

### Размеры dist (v0.9, для проверки после сборки)

| Скрипт | Что делает |
|---|---|

| `props.py` | касуга-доро, тории с симэнавой, колокол бонсё |
| `env.py` | минка, сёдзи, заборы, пугала, телега, колодец, бамбук, камни, цуйдзи, хондо, сёро, кагариби, PBR-земля |
| `anim.py` | анимации героя → Actions на суставах `AK__J_*`, NLA-дорожки, IK руки к рукояти, мечи `AK__J_swR/swL`. Клипы: обнажение, ножны с тибури, idle-подбрасывание, атаки R1/R2/R3/L1/L2/L3/N/X. Запекается в `game/src/anims.js` |
| `loot.py` | сундук (крышка на шарнире `LT__J_chest__lid`, печать симэнава с о-фуда), ключ, записка, 8 предметов (хётан, флакон, омамори, точильный камень, курильница, свиток, маска Но, бэнто) |
| `house.py` | **v0.9**: усадьба — фасад с энгавой, стены/полы/потолки, татами, сёдзи, фусума, токонома, тансу, книжные шкафы, витрины с доспехами, ширмы-бёбу, андоны, ирори, кухня, футоны, сад со снегом, додзё; ёкаи дома; предметы дома |
| `tex.py` | процедурные PBR-текстуры (ткань, кодзанэ, кожа, волосы, сталь, хамон, смола, солома, дерево, камень, кость, бумага) |
| `fetch_tex.py` | CC0-текстуры Poly Haven (указано в README) |

**Соглашение об именах:** `PREFIX__часть__деталь`. Геометрия запекается в локальные координаты сустава. Специальные меши: `cape`, `orb`, `horn\d`; точки-маркеры с суффиксом `TIP` дают `ASSET.tips`.
Детали `sk_*` (юбка хакамы, кусадзури, концы оби) скиннятся на GPU к бёдрам/ногам, чтобы ноги не проходили сквозь ткань.

**Загрузка:** `assets.js` → `loadAssets()` собирает base64 из `window.__NITEN_ASSETS_PARTS` / `__NITEN_LOOT_PARTS` / `__NITEN_HOUSE_PARTS` (или из инлайн-переменных `__NITEN_ASSETS` / `__NITEN_LOOT` / `__NITEN_HOUSE` в single-файле), парсит GLB, раскладывает меши по `ASSET.parts[pre+'__'+part]`, материалы в `ASSET.mats[material.name]`.

## 7. Тестирование (headless)

Ключевой инструмент — `/data/work/t.cjs` (Playwright + Chromium + SwiftShader).

```bash
rm -f /data/work/s*.png
CHR=$(which chromium) SETUP="<js>" PLAN='[[nUpdates,"<js>"],...]' WT=600 timeout 600 node /data/work/t.cjs
```
- Загружает `file:///data/repo/NITEN_3D_single.html`, ждёт исчезновения `#ld` и появления `window.__upd`.
- `SETUP` — JS, исполняемый один раз в контексте страницы.
- `PLAN` — массив пар `[сколько кадров прокрутить, какой JS выполнить перед этим]`.
- `WT` — мс ожидания на шаг (по умолчанию 700; для headless ставить 600).
- Пишет `/data/work/s0.png`, `s1.png`, … и лог состояния в stdout:
  `{t, on, k, P:[x,y,z,state,drawn], ch, e:[state:y,…]}`.
- В конце печатает первые 15 ошибок/варнингов консоли и `pageerror`.

### Просмотр результата
```bash
montage /data/work/s0.png /data/work/s1.png ... -tile 3x3 -geometry 480x270+2+2 -quality 80 /data/work/a.jpg
```
⚠️ Не использовать глоб `s[0-8].png`, если кадров меньше — montage упадёт, а старый `a.jpg` останется и введёт в заблуждение. Всегда `rm -f s*.png` перед тестом.

### Хелпер точечных правок
`/data/work/rep.py`:
```python
rep('gH.js', 'старая строка', 'новая строка')
```
Путь считается относительно `/data/repo/game/src/`. Для README: `rep('../../README.md', ...)`.
Если строка не найдена — печатает `MISSING <файл> <первые 70 символов>`.

### Готовые SETUP-рецепты
**Дуэль (глава 2, колокол):**
```js
__G.mode='play';__load(2);__CS.on=false;__P.z=-6;__upd(500);__G.subs=[]
```
Дверь усадьбы: `__LV().duelOpen=true;__P.x=0;__P.z=-27;__door()`

**Дом (глава 3):**
```js
__G.mode='play';__G.ambushDone=true;__load(3);__CS.on=false
```
⚠️ `ambushDone=true` ставить **до** `__load(3)`. Иначе остаётся враг `csIdle` из засады и бои в комнатах не завершаются.
- Засада: `__G.ambushDone=false`, затем `__P.x=2;__P.z=-11.6`.
- Очистка комнаты: `__G.hcleared.add('<id>')`.

### Ограничения тестов
- Headless на SwiftShader даёт **1–4 fps** — реальная производительность не измеряется.
- **Звук не прослушан** (headless).
- Победа над боссом проверялась через `__kill(e)`, а не полноценным боем.

## 8. v0.9 «Забытый дом» — главная актуальная фича

### Вход в главу
1. После победы над Сотой (`bossDown === 'sota'`) герой получает **записку** и **ключ дома** (`housekey`).
2. Катсцена ключа: `startHouseKeyCS`.
3. Дверь усадьбы за двором колокола: дом в `(0, 0, −34)`, дверь на `z = −28.95`.
4. `startDoorCS` → `loadChapter(3)` → `startHouseArrival`.
5. Старт игрока — прихожая, `P.z = −14.6`.

### Комнаты (`HR` в `gH.js`)
| id | Название | x0..x1 | z0..z1 | h | пол | потолок |
|---|---|---|---|---|---|---|
| `genkan` | Прихожая | −3.5..3.5 | −17..−11 | 3.2 | stone | cedar |
| `hall` | Зал предков | −10..10 | −11..5 | 6.8 | floor | cedar |
| `study` | Кабинет | −20..−10 | −11..−3 | 3.2 | tatami | hinoki |
| `bed` | Спальня | −20..−10 | −3..5 | 3.2 | tatami | hinoki |
| `store` | Кладовая | 10..20 | −11..−3 | 3.2 | cedar | cedar |
| `kitchen` | Кухня | 10..20 | −3..5 | 3.6 | floor | cedar |
| `garden` | Внутренний сад | −10..10 | 5..15 | 0 | snow | — |
| `dojo` | Додзё | −10..10 | 15..25 | 5 | hinoki | cedar |

Стены описаны массивом `HW`: `[ось, координата, от, до, высота, проёмы[[a,b,тип]]]`. Типы проёмов: обычный, `door`, `gate`, `exit`.
Галерея в зале — **только декоративная**, не ходибельная.

### Засада (`startAmbushCS`)
Самурай атакует сверху, Акира отбивается лёжа, бросает Ёи, клинок ломается.
Ставятся `G.oneBlade = true` и `addItem('yoihilt')`. После этого **ПКМ = удар перчаткой Они** (`ATK.LG`) вместо удара Ёи.

### Бои
- Волны `HWAVES` по комнатам, решётки-барьеры (`setBars`, `endRoomFight`).
- После зачистки комнаты печати сундуков сгорают и падают ключи.
- Сад открывает ворота в додзё.

### Враги дома
| Тип | Поведение |
|---|---|
| `musha` — самурай-призрак | комбо, рывок, иай |
| `chochin` — Тётин-обакэ | прыжки, язык |
| `moku` — Мокумокурэн | самонаводящиеся орбы, **отражаются блоком** |
| `shogun` — **босс** «Кагэмару, Страж Дома» | hp 900, 2 фазы; при hp < 50 % призывает фонари |

`houseBossDown` открывает выход; спот `exit` в `(0, 23.9)` → `startExitCS` → экран победы «Путь Меча».

### Сундуки (`HCH`, 7 шт.)
- Обычные: `hall (−8.8, −10.25)`, `store (17.6, −10.35)`, `kitchen (11.3, 4.3)`, `dojo (−7, 24.0)`.
- Тайники (3): за книжным шкафом `shelf (−19.35, −7)`, спот `(−19, −7)`; под татами `tatami (−17.5, −1.2)`, спот `(−16.6, −1.2)`; в сугробе `snow (8, 13.6)`, спот `(8, 12.4)`.

### Карта (`drawMap`, клавиша M)

## 10. Пуш в GitHub (единственный рабочий способ)

Локальный git не использовать. Только **GitHub MCP `push_files`**.

```bash
# 1. собрать payload
python3 /data/work/mk.py "сообщение коммита" путь1 путь2 ...
# 2. запушить
```
Затем:
```
mcp_run_tool(server_name="GitHub", tool_name="push_files",
             arguments_file_path="/data/work/ps.json")
```

`mk.py`:
```python
import json,sys,os
files=sys.argv[2:]
json.dump({"owner":"SoraMasora","repo":"niten-put-dvuh-dush","branch":"main",
           "message":sys.argv[1],
           "files":[{"path":f,"content":open('/data/repo/'+f).read()} for f in files]},
          open('/data/work/ps.json','w'),ensure_ascii=False)
print(os.path.getsize('/data/work/ps.json'))
```
Пути — относительно `/data/repo`. Скрипт печатает размер payload.

**Правила:**
- Payload ≤ **1 МиБ**. При превышении — пушить файлы по одному.
- Большие файлы (каждый `partNN.js`/`houseNN.js` ≈ 990 КБ) — **отдельным коммитом на файл**. Примеры готовых payload: `ps_house00.json` … `ps_house05.json`, `ps_g1.json`, `ps_g2.json`.
- Последовательно надёжнее, чем параллельно (параллельные пуши в этой сессии прошли, но это не гарантия).
- **Проверка:** `get_file_contents` по пути и сравнение sha с `git hash-object <файл>` локально.

## 13. Известные ограничения и открытые задачи

**Ограничения (не баги, а осознанные/непроверенные места):**
- Headless-тест даёт 1–4 fps — производительность на реальном железе не измерена.
- Звук не прослушан ни разу (нет аудио-выхода в песочнице).
- Победа над боссом дома проверялась через `__kill`, полный бой не пройден.
- Позы в катсценах — процедурные ключевые кадры, не захват движения.
- Галерея в зале не ходибельная (декор).
- Пруд в саду почти чёрный (визуальная недоработка).
- Белые вспышки, если несколько врагов умирают одновременно.
- Текстуры дома — CC0 Poly Haven (указано в README).
- `NITEN_3D_single.html` (15.8 МБ) не коммитится — его надо пересобирать локально.

**Естественные следующие шаги:**
- Пройти дом целиком «как игрок» и вычистить оставшиеся визуальные огрехи (пруд, вспышки).
- Продолжить сюжет после «Забытого дома» (глава 6+).
- Настроить GitHub Pages для `dist/` (README уже упоминает такую возможность).

4. Обновить README, если фича пользовательская.
5. Резервный коммит кода.
6. Если менялся `dist` — отдельные коммиты по каждому крупному файлу.
7. Проверить sha через `get_file_contents` + `git hash-object`.
8. Отдать пользователю краткий отчёт: что сделано, что проверено, что осталось.
